## Decisions

- **Parser ported from `~/workspace/phext/parse_phext.py`** (Will's verified
  dead-reckoning parser): same delimiter bytes
  (0x01, 0x1F, 0x1E, 0x1D, 0x1C, 0x1A, 0x19, 0x18, 0x17), same
  increment-and-reset walk, same trailing-empty-scroll rule, byte-level
  walk with per-scroll UTF-8 replacement decoding.
- **Content read via plain HTTP fetch** to `INK_OS_URL` + `contentPath`
  with the app-token Bearer header, *not* via the injected SDK client,
  whose `request()` JSON-parses responses (a phext is not JSON).
- **No `pending` leg**: rendering is synchronous and CPU-only, so `run`
  always answers `completed` (or `failed` on error). `/adapter/runs/…`
  answers `failed` — no job can ever exist.
- **Determinism by construction**: no clocks/randomness/env in the render
  path; the output depends only on the source bytes and title.
- One bug was caught by the harness during the build and fixed: the
  module's exported handler is named `fetch`, which shadowed the global
  `fetch` used for the content read; the module now binds
  `globalThis.fetch` as `httpFetch`.
