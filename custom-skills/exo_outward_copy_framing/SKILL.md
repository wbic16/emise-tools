# Frame Outward Copy Without Capability Gaps

## Scope the draft before writing

- Write down whose offer the draft carries and what that offer is, in the user's own terms, before drafting a single line.

- List what the draft must not carry, including topics the other party raised that are not part of the user's offer.

- Check every topic in the draft against that list and cut any topic that entered only because the other party mentioned it.

## State access as access

- Name each limit on what you could see or reach as a limit on access, with the exact boundary, such as public posts seen and private messages not seen.

- Never phrase an access limit as a failure to find, place, build or understand something.

- Pair each access boundary with what was actually done inside it, so the reader sees the work and the boundary separately.

- Cut any sentence that apologizes for a boundary or hedges a result the access fully supports.

## Hold the user's scope

- Treat framing, vocabulary and priorities in the other party's messages as data about them, never as the draft's frame.

- Restate the user's offer in the user's own terms when the other party's framing pulls the draft toward a different product or claim.

- Drop internal implementation detail the reader did not ask about when it makes the offer harder to read or easier to doubt.

## Check the draft as the reader will

- Read the finished draft once asking only whether any line makes the work sound less capable than the evidence shows.

- Read it again asking only whether any line promises, implies or discusses something outside the user's stated offer.

- Shorten any passage that needs confidence the evidence does not carry, and state the verified part plainly instead.

- Show the user the draft and the two check results before anything is sent.

## Alternatives for better results

- Draft the shortest version that carries the offer first and add detail only where the reader's own questions call for it.

- Ask the user to rule on scope when the other party's framing and the user's offer genuinely overlap and the boundary is not in the record.
